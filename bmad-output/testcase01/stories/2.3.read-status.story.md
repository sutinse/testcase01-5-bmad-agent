# 2.3: Tallennetun tilan luku

**Story ID:** 2.3
**Epic:** 2 - Erillinen päätös ja tilan näkyvyys
**Slug:** read-status
**Status:** backlog

## Story

As a **oikeutettu käsittelijä**,
I want **lukea palautuksen nykytilan**,
so that **näen myös erillisen päätöksen tuloksen**.

## Acceptance Criteria

1. `GET /api/v1/refund-approval-checks/{refundId}` vaatii validoidun `refund-system`-roolin ja `sub`:n; myös muu oikeutettu käsittelijä kuin alkuperäinen saa vastauksen.
2. Olemassa oleva `PENDING`, `ALLOWED` tai `BLOCKED` palautuu HTTP 200 JSON:ssa vastaavalla `allowed`-arvolla ja muuttumattomalla alkuperäisellä `processorId`:llä; GET ei kirjoita tietokantaan.
3. Tuntematon `refundId` antaa 404 `application/problem+json`; puuttuva/väärä token tai rooli ei paljasta palautuksen tietoja.

## Tasks / Subtasks

- [ ] Toteuta ohut GET-resurssi repositoryn lukureitillä (AC: #1, #2).
- [ ] Käytä samaa tallennetun nykytilan vaste-esitystä kuin lähetyksessä ja päätöksessä (AC: #2).
- [ ] Suunnittele toisen käsittelijän, kaikkien kolmen tilan sekä kieltojen testit (AC: #1, #2, #3).

## Testing

- **Approach:** HTTP-integraatiotestit kahden processor-tokenin ja päätetyn rivin kanssa.
- **Key scenarios:** PENDING, ALLOWED, BLOCKED, eri käsittelijä, virheellinen token ja puuttuva id.
- **Per-AC verification:** AC #1: kaksi sallittua tokenia; AC #2: JSON-tilat ja muuttumaton tietokanta; AC #3: 404/401/403 ilman tilatietoa.
- **Fixtures / mocks:** tallennettu rivi ja kaksi `refund-system`-tokenia.
- **Edge cases to cover:** alkuperäisestä eroava `sub` heti päätöksen jälkeen.
